# BIUM 1차 MVP 종합 UI/UX 디자인 및 화면 가이드 프롬프트

> 이 문서는 프론트엔드(윤상은)가 화면을 구현할 때 참고하는 디자인 가이드이자, AI 페어프로그래밍 도구(Claude Code 등)에 그대로 붙여넣어 컴포넌트를 생성·수정할 때 쓰는 프롬프트다.
> 데이터 구조·API 계약은 여기서 새로 정의하지 않는다 — `docs/api-contracts/routing.md`와 `frontend/src/types/routing.ts`에 이미 합의된 필드(camelCase: `isRecommended`, `minutePerImprovement`, `netOnboardRemaining`, `congestionPct`, `extraMinVsFastest` 등)를 그대로 쓴다. 이 문서는 "그 데이터를 어떻게 보여줄지"만 다룬다.

## 1. 톤앤매너 및 비주얼 컨셉

**핵심 인사이트 → 비주얼 번역**: "텅텅"은 대량 하차 직후 "텅텅 비어버린" 여유 좌석/공간을 뜻한다. 디자인도 그 여유감·시원함을 화면의 여백(whitespace)과 색으로 번역해야 한다.

- 레퍼런스: 토스(간결한 타이포 + 플랫 아이콘 + 명확한 상태 컬러), 카카오바이크(민간 모빌리티 특유의 경쾌하되 신뢰감 있는 느낌).
- 지향점: **관제센터/공공데이터 대시보드 느낌 ❌** / **가볍고 개인화된 스마트 모빌리티 앱 느낌 ⭕**
- 컬러 시스템 (Cool & Clear 방향):
  - Background: 거의 흰색에 가까운 Cool Gray (`#FFFFFF` ~ `#F7F9FB`)
  - Primary(브랜드 강조): 시원한 블루 또는 민트 중 택1 — 예: 토스 블루 계열 `#3D7BFF`, 또는 카카오바이크 민트 계열 `#12B5A6`. 검색/CTA 버튼, 추천 배지 등 강조가 필요한 곳에만 제한적으로.
  - Text: 거의 블랙에 가까운 Neutral (`#1A1D29`), Sub Text: Neutral Gray (`#8B93A7`)
  - **주의**: 4단계 혼잡도 컬러(§3)는 브랜드 Primary와 색 충돌이 없도록 별도 팔레트로 관리한다 — 상태 정보(위험/경고)와 브랜드 강조색이 섞이면 "이게 지금 위험하다는 뜻인지 추천이라는 뜻인지" 혼동이 생긴다.
  - > ⚠️ 참고: 이전 스프린트에서 "Warm Mobility"(웜 아이보리/테라코타 코랄) 톤으로 한 차례 리디자인한 이력이 있다. 이번 브리프는 그와 결이 다른 "쿨/스마트" 방향이라, 실제 구현 전에 팀 내에서 최종 톤 하나로 확정해야 한다(교체할지, 이번 브리프를 새 기준으로 삼을지).
- 타이포그래피: Pretendard/Inter 계열 Sans-serif. 숫자·시간·%처럼 자리가 흔들리면 안 되는 값은 tabular-nums 또는 모노스페이스로 고정.
- 아이콘: Line icon 하나로 통일(24px 그리드, stroke 1.5~2px). 교통수단 아이콘도 같은 스타일로 — 만화적/입체적 아이콘 금지.

## 2. 메인 화면 및 검색 UX

- Hero 이미지 같은 장식 영역 없이, 검색 폼이 화면의 주인공이다 — "빠르게 입력 → 바로 결과"가 이 앱의 핵심 흐름.
- 출발지/도착지: 두 인풋을 하나의 카드에 담고 사이에 스왑(⇄) 버튼. 현재 구현된 `RouteSearchForm`의 구조는 그대로 두고 스타일 완성도만 높인다.
- 기준시간 UX (출퇴근 서비스의 핵심 차별점):
  - 기본은 "지금 즉시" 토글 + 자주 쓰는 시간대 프리셋 칩 2개(예: "오전 8시 출근", "오후 6시 퇴근")를 원탭으로 제공 — 매번 시간을 직접 스크롤/타이핑하게 만들지 않는다.
  - 기존 `<input type="time">`은 그대로 유지하고, 프리셋 칩을 누르면 그 값으로 채워지는 방식으로 붙인다 (기능 변경 없이 입력 단축키 역할만 추가).
- 즐겨찾기(`FAVORITE_STOPS`)는 텍스트 버튼보다 "자주 가는 곳" 카드형 칩으로, 역/정류장 구분 아이콘을 함께 표시.
- 탐색 버튼은 화면 하단에 sticky로 고정 — 폼이 길어져도 항상 원탭 거리에 있어야 한다.

## 3. 결과 목록 화면 (Result List)

**카드 정보 위계** (위에서부터 시각적 강조 순서):
1. 추천 배지 + 총 소요시간
2. 4단계 혼잡도 컬러 인디케이터
3. 멀티모달 아이콘 칩 시퀀스
4. 보조 정보(분당개선, 최단경로 대비 추가시간)

**추천(`isRecommended`) 카드**
- `isRecommended: true`인 카드는 리스트 최상단에 고정하고, 카드 테두리를 브랜드 Primary 컬러로 강조 + 설명형 배지 부착(숫자 배지보다 "가장 여유로운 경로" 같은 문장형이 사용자에게 더 잘 읽힌다).
- `minutePerImprovement`(분당개선)는 숫자 그대로 노출하지 않고, "○분 더 걷고 △명 덜 혼잡해요"처럼 사람이 바로 이해하는 문장으로 변환해서 보여준다.

**4단계 컬러 인디케이터** (지하철 `congestionPct`(%)와 버스 `netOnboardCount`(명)처럼 단위가 다른 두 지표를 하나의 척도로 정규화):

| 단계 | 기준(예시) | 색 |
|---|---|---|
| 여유 | 혼잡도 < 40% | Green / Mint |
| 보통 | 40~60% | Yellow / Amber |
| 혼잡 | 60~80% | Orange |
| 매우 혼잡 | 80%+ | Red |

- 화면에는 항상 정규화된 4단계 컬러 라벨만 보여주고, 원본 % / 인원수 같은 raw 숫자는 상세화면에서만 노출한다.
- 색맹 사용자 대응: 색상만으로 구분하지 않고 밀도가 다른 아이콘(예: 사람 아이콘 개수/농도)을 색과 병행 표시.
- 구현은 카드 왼쪽의 얇은 vertical bar 또는 상태 dot 배지로.

**멀티모달 아이콘 칩**
- `modes` 배열 순서대로 아이콘 칩을 나열(도보 → 지하철 → 버스 → 따릉이, 사이에 "›" 구분자).
- 아이콘은 §1의 라인 아이콘 스타일로 통일하고 색은 뉴트럴로 — 색상은 혼잡도 인디케이터에만 사용해서, "어디에 색이 있으면 상태 정보"라는 규칙을 화면 전체에서 일관되게 유지한다.

## 4. 지도 및 경로 상세 화면 (Map & Detail)

- **폴리라인 컬러 코딩**: `steps[]`에 `congestionPct`/`netOnboardCount`가 있는 구간만 §3의 4단계 컬러로 세그먼트별로 착색하고, 정보가 없는 도보(`WALK`) 구간은 뉴트럴 점선으로 표시. 경로 전체를 한 가지 색으로 그리지 않고 구간마다 색이 바뀌는 것 자체가 "BIUM"의 핵심 차별화 시각 요소이며, 서비스를 대표하는 스크린샷이 되어야 한다.
- **마커/말풍선**:
  - "대량 하차 직후" 포인트: 일반 정차 마커와 형태를 다르게(예: 속이 빈 원 vs 꽉 찬 원, 또는 "-42명" 말풍선)하고, 탭하면 "이 역에서 다수 하차 → 여유 좌석 확보" 같은 설명 툴팁을 띄운다.
  - 따릉이 환승 지점: 자전거 아이콘 마커 + 실시간 대여소 재고 수 배지.
  - 말풍선 색은 §1의 Surface/Primary만 사용해서 지도 위에서도 브랜드 톤을 유지한다.
- 지도 자체는 과하게 꾸미지 않는다 — 라인 두께를 얇게, 배경은 저채도로 눌러서 경로선(컬러 코딩된 폴리라인)이 지도보다 시각적으로 위에 있도록 명도 대비를 확보한다.

## 5. 4일 단기 스프린트 타협안 (TailwindCSS 기반)

> 현재 코드는 순수 CSS(변수 기반 `tokens.css`)로 되어 있다. 아래는 Tailwind로 전환한다고 가정할 때의 우선순위 제안이며, 실제 전환 여부는 윤상은과 먼저 합의한다.

- **Day 1**: 컬러/타이포/spacing 토큰을 `tailwind.config.js`의 `theme.extend`에 먼저 고정 → 이후 모든 화면이 유틸리티 클래스만으로도 통일된 톤을 유지하게 한다.
- **Day 2**: 메인 검색 화면 + 결과 리스트 화면(지도 없이 리스트만). 정보 위계상 가장 중요한 두 화면이라 최우선.
- **Day 3**: 지도 화면(폴리라인 컬러 코딩 + 마커). 시각적으로 가장 인상적이지만 구현 난이도가 높아 리스트 화면이 끝난 뒤 착수.
- **Day 4**: 버퍼 + QA + 반응형(모바일 웹 기준) 정리. 신규 기능 추가 금지, 이미 만든 화면의 여백·정렬·엣지케이스(경로 0개/로딩/에러)만 다듬는다.
- **타협 원칙**: "모든 구간에 커스텀 아이콘"류의 디테일보다 "정보 위계(추천 배지 → 혼잡도 색 → 나머지)가 먼저 맞는 것"이 우선이다. 컴포넌트는 Tailwind 기본 유틸리티 + 단순 컴포넌트 분해로 최대한 빠르게 구성하고, 커스텀 애니메이션이나 복잡한 인터랙션은 이번 스프린트 범위 밖으로 명확히 자른다.
